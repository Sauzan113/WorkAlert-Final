# Feasibility Analysis – WorkAlert

## 1. Technical Feasibility (Can We Build It?)
* **Familiarity with Application:** Moderate-High. The team is familiar with modern job boards and messaging workflows.
* **Familiarity with Technology:** High. The team has hands-on coursework experience with React, Tailwind CSS, Node.js, Axios, and relational databases (PostgreSQL/MySQL).
* **Project Size:** Moderately Low. Scoped specifically to core job discovery, posting, and applicant-employer messaging for a 6-person team.
* **Compatibility:** High. Built as a standard browser-based web application compatible with modern desktop and mobile browsers.

## 2. Economic Feasibility (Should We Build It?)
* **Development Costs:** Minimal direct monetary cost (utilizing open-source frameworks, free-tier cloud/database hosting, and student development hours).
* **Operational Costs:** Low ongoing hosting and database maintenance expenses.
* **Benefits:** High educational and portfolio value, demonstrating end-to-end SDLC execution and delivering a functional local job-matching prototype.

## 3. Organizational Feasibility (If We Build It, Will They Use It?)
* **Strategic Alignment:** Directly satisfies course requirements for full-stack software engineering and systems analysis.
* **Stakeholders:** Project team members (developers/analysts), course instructor (sponsor/evaluator), job seekers (end users), and local employers (end users).
