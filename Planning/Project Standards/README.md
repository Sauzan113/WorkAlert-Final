# Project Standards – WorkAlert

## Documentation Standards
* All project deliverables are stored in their designated SDLC phase folder in this GitHub repository.
* Every folder contains a `README.md` summarizing its contents and linking to supporting files (`.docx`, `.xlsx`, diagrams).
* File names use clear, descriptive names without duplicate suffixes (e.g., `RTM_WorkAlert.xlsx`).

## Coding Standards
* **Frontend:** React with Tailwind CSS and Axios for API communication.
* **Backend:** Node.js / Express RESTful API architecture with modular route and controller files.
* **Database:** Relational schema in PostgreSQL/MySQL with normalized tables and clear foreign key constraints.
* **Version Control:** Descriptive commit messages summarizing the phase or feature updated.

## Procedural Standards
* All changes to core requirements must be reflected in both the SRS (`WorkAlert_SRS_Version_2.docx`) and the Requirements Traceability Matrix (`RTM_WorkAlert.xlsx`).
* Major deliverables are reviewed by the team prior to submission deadlines.
