# Risk Assessment – WorkAlert

## Risk #1: Scope Creep During Feature Implementation
* **Likelihood of Risk:** High
* **Potential Impact on Project:** Adding extra features late in the semester could delay core job search, messaging, and testing deliverables.
* **Ways to Address This Risk:** Strictly enforce the requirements baseline defined in `WorkAlert_SRS_Version_2.docx` and defer non-essential enhancements to future releases.

## Risk #2: Integration Delays Between Frontend, Backend, and Database
* **Likelihood of Risk:** Medium
* **Potential Impact on Project:** Mismatched API payloads or database schemas could slow down end-to-end integration testing.
* **Ways to Address This Risk:** Finalize API endpoints and database schemas early in the Design phase and test endpoints incrementally using Postman/REST clients.

## Risk #3: Uneven Workload or Schedule Conflicts Across Team Members
* **Likelihood of Risk:** Medium
* **Potential Impact on Project:** Overlapping university exams and assignments could delay individual deliverables.
* **Ways to Address This Risk:** Track responsibilities clearly using the [RACI Matrix](./../Staffing%20Plan/WORKALERT_RACI_Matrix.xlsx), hold regular check-ins, and redistribute tasks early if a member faces a bottleneck.
